# 첫 화면 UI/UX 리뷰 및 재디자인

> 작성일: 2026-09-12
> 관련 문서: [004-landing-page.md](004-landing-page.md), [design-brief.md](../design-brief.md)

---

## 1. 한 줄 요약

`index.html`(프로필 입력 폼)을 UI/UX 관점으로 점검해 발견한 문제 중 30분 안에 고칠 수 있는 것부터 고치고, 이후 `ui-ux-pro-max` 스킬로 색상·폰트·레이아웃까지 다시 잡았다. 이어서 사용자가 준 레퍼런스(옛 Instagram 로고)를 기준으로 히어로 영역을 파란 그라데이션 + 필기체 로고로 다시 디자인하고, `match.html` 색상도 같은 팔레트로 통일했다.

## 2. 왜 만들었는가

004에서 폼 화면은 만들었지만 디자인 품질을 따로 점검한 적은 없었다. 다음 기능(정책 매칭)으로 넘어가기 전에, 지금 있는 화면부터 실제 사용자가 쓰기 불편한 부분은 없는지 먼저 짚고 넘어가기로 했다.

## 3. 구현한 것

### 3-1. UI/UX 리뷰로 찾은 문제와 30분 내 수정

리뷰 결과 문제를 심각도순으로 5개 뽑았고, 그중 바로 고칠 수 있는 3개를 수정했다.

| 문제 | 수정 |
|---|---|
| 필수/선택 입력이 화면에서 구분 안 됨 | 개인특성 라벨에 `(선택)`, 관심분야 legend에 `*`와 "1개 이상 선택해주세요" 표시 |
| 관심분야 0개 선택해도 제출됨 → 이후 매칭이 무조건 실패 | 제출 시 체크된 항목이 0개면 저장을 막고 빨간 글씨로 안내 |
| 제출 성공 메시지가 일반 텍스트라 확신을 주기 어려움 | 초록 글씨 + `✓` 표시로 강조 |

나머지 2개(제출 후 다음 화면 없음, 전체적인 시각 위계 부족)는 각각 007에서 만든 매칭 화면 연결, 아래 3-2 재디자인으로 해결했다.

### 3-2. `ui-ux-pro-max` 스킬로 재디자인

GitHub에서 설치한 `ui-ux-pro-max` 스킬(UI 스타일·색상·폰트 조합을 검색해 추천해주는 로컬 데이터셋 기반 스킬)로 다음을 결정했다.

- **폰트**: Noto Sans KR — 화면이 전부 한글이라, 한글 글리프가 없는 라틴 전용 폰트를 쓰면 한글은 결국 브라우저 기본 폰트로 대체돼 화면마다 느낌이 들쭉날쭉해지는 문제를 피하기 위해
- **색상**: 파랑 계열(`#3182f6`) — 스킬이 처음 추천한 fintech 팔레트(금색+보라 다크 크립토 톤)는 우리 타깃(2030 대학생·사회초년생)에게 안 맞아서, 국내에서 익숙한 신뢰감 있는 블루로 다시 잡음
- **레이아웃**: 폼 전체를 `<article>` 태그로 감싸 카드 형태로 만들고, 헤더 위계(제목 크게/부제 흐리게)와 입력 항목 간 여백을 정리

### 3-3. 레퍼런스 기반 히어로 재디자인 + 시작하기 아코디언 UX

사용자가 "Polistagram" 네이밍의 유래인 옛 Instagram 로고(파란 그라데이션 배경 + 필기체 로고) 이미지를 레퍼런스로 줘서, 이를 기준으로 다시 디자인했다.

- **폰트**: 로고 "Polistagram" 글자에만 Google Fonts `Yellowtail`(필기체)을 적용. 본문·폼 라벨은 여전히 Noto Sans KR 유지 (한글은 필기체 지원이 없어서 로고 텍스트에만 국한)
- **색상**: 3-2에서 잡은 팔레트를 레퍼런스의 파란 톤(`#3a6ea5`)으로 다시 교체. `--pico-primary` 계열 변수를 전부 이 톤으로 바꿔서 버튼·체크박스·포커스 색이 한 번에 따라오게 함
- **레이아웃**: `<main class="container">` 바깥에 `.hero`를 새로 둬서, 로고+소개문구+"시작하기" 버튼이 있는 영역만 화면 폭 전체를 파란 그라데이션(`linear-gradient(135deg, #4a80b3, #2c4a68)`)으로 채움. 폼 카드는 히어로 아래 흰 배경 위에서 살짝 겹치게 배치(`margin-top: -3rem`)
- **인터랙션**: 처음엔 프로필 폼이 접혀 있다가(`max-height: 0`), "시작하기" 버튼을 누르면 `.open` 클래스가 붙으면서 `max-height`/`opacity`가 `transition`으로 부드럽게 펼쳐짐. 목적은 첫 화면을 히어로만 있는 깔끔한 랜딩으로 만들고, 폼은 사용자가 "시작"을 선택했을 때만 보여주는 것

### 3-4. `match.html` 팔레트 통일

`match.html`은 3-2 이전에 만든 로즈 계열 팔레트(`#fff1f2` 배경, `#e11d48` 카드 타이틀)를 그대로 쓰고 있었는데, 히어로가 파란 계열로 바뀌면서 두 화면의 톤이 어긋났다. 배경(`#eaf2fa`)과 `.card.indirect .card-title` 색(`#3a6ea5`)을 index.html과 같은 블루 톤으로 맞춰서 화면 간 일관성을 회복했다.

## 4. 동작 흐름

이번 작업은 데이터 흐름 변경이 아니라 **같은 화면의 검증 로직 + 스타일**만 바꾼 것이라 별도 다이어그램은 없다.

## 5. 주요 파일

- `index.html`: 폼 검증 로직(관심분야 0개 방지), 성공/실패 메시지 스타일, 히어로 영역, "시작하기" 아코디언 토글, 폰트·색상·레이아웃 전부 이 파일 안에 있음 (빌드 도구 없는 단일 파일 구조 유지)
- `match.html`: 배경색·카드 타이틀 색을 index.html과 같은 블루 팔레트로 통일

## 6. 핵심 코드 / 개념

**필수 조건 안 맞으면 함수를 일찍 끝내기**

```javascript
if (checkedInterests.length === 0) {
  message.style.color = "crimson";
  message.textContent = "관심분야를 1개 이상 선택해주세요.";
  return;
}
```

`return`을 여기서 만나면 함수가 즉시 끝나서, 아래에 있는 `localStorage.setItem(...)`(저장하는 코드)까지 도달하지 못한다. "조건이 안 맞으면 저장을 막는다"는 동작을 이 한 줄로 구현했다.

**Pico.css 변수 덮어쓰기로 전체 톤 바꾸기**

```css
:root {
  --pico-font-family: "Noto Sans KR", sans-serif;
  --pico-primary: #3182f6;
}
```

Pico.css는 버튼·링크·포커스 효과 색을 전부 `--pico-*` 변수로 관리한다. 이 변수들을 `:root`에서 다시 정의하면, 태그 하나하나에 클래스를 붙이지 않아도 화면 전체 색·폰트가 한 번에 바뀐다.

**`<article>` 태그로 카드 레이아웃 얻기**

Pico.css는 `<article>` 태그에 기본으로 테두리·배경·둥근 모서리를 입혀준다. 새 CSS를 안 써도 폼 전체가 카드 한 장처럼 보인다.

**`max-height` 트랜지션으로 접었다 펼치기**

```css
#profile-section {
  max-height: 0;
  opacity: 0;
  overflow: hidden;
  transition: max-height 0.5s ease, opacity 0.4s ease;
}
#profile-section.open {
  max-height: 2000px;
  opacity: 1;
}
```

```javascript
startBtn.addEventListener("click", () => {
  profileSection.classList.add("open");
});
```

`display: none` ↔ `display: block`은 0 아니면 1이라 애니메이션이 안 되지만, `max-height`는 숫자값이라 CSS `transition`이 그 사이 값을 부드럽게 채워준다. 그래서 "접혀 있다가 펼쳐지는" 느낌을 순수 CSS + 클래스 토글만으로 구현할 수 있었다.

## 7. 사용한 기술

| 기술 | 하는 일 |
|---|---|
| `ui-ux-pro-max` (GitHub에서 설치한 Claude 스킬) | UI 스타일/색상/폰트 조합을 로컬 데이터셋에서 검색해 추천 |
| Google Fonts (Noto Sans KR, Yellowtail, CDN) | 한글 지원 본문 폰트 + 로고 전용 필기체 폰트 |
| Pico.css CSS 변수(`--pico-*`) | 프레임워크 없이 전체 테마를 한 번에 바꾸는 방법 |
| CSS `transition` + `max-height` | JS 애니메이션 라이브러리 없이 접기/펼치기 구현 |

## 8. 문제와 해결

- **문제**: `ui-ux-pro-max`가 처음 추천한 색상 팔레트(fintech/crypto 다크 테마)가 서비스 톤과 안 맞았다
- **원인**: 스킬의 팔레트 데이터가 "핀테크"라는 키워드에 맞춰 거래소·크립토 앱 느낌으로 매칭됐다
- **해결**: 색상만 따로 다시 검색해서, 국내 2030 타깃에 맞는 블루 계열로 교체
- **배운 점**: 추천 도구의 첫 결과를 그대로 쓰지 않고, 실제 타깃·톤에 맞는지 한 번 더 검증해야 한다

- **문제**: 히어로 재디자인 직후, 이전에 프로필을 한 번 저장해둔 브라우저에서는 페이지를 열자마자 폼이 펼쳐진 채로 보였다
- **원인**: `restoreProfile()`이 "저장된 프로필이 있으면 폼에 값을 채우고 + 폼도 자동으로 펼친다"로 구현돼 있었다. 재방문자가 "시작하기"를 또 누르지 않게 하려는 의도였지만, "첫 화면은 항상 히어로만 보여야 한다"는 요구와 충돌했다
- **해결**: `restoreProfile()`에서 값 채우기만 남기고 `profileSection.classList.add("open")` 호출을 제거. 폼은 언제나 "시작하기" 버튼을 눌러야만 펼쳐지도록 통일
- **배운 점**: "편의 기능"이 다른 요구사항(여기선 첫 화면 레이아웃)과 부딪힐 수 있으니, 자동화 로직을 추가하기 전에 "항상 이렇게 동작해야 한다"는 화면의 기본 규칙부터 먼저 확인해야 한다

## 9. 의사결정

- **왜 UI/UX 리뷰의 5개 문제 중 3개만 지금 고쳤나** — 나머지 2개(다음 화면 부재, 전체 위계)는 각각 뒤따르는 기능(매칭 화면)과 이번 재디자인으로 자연스럽게 해결되는 항목이라, 별도로 급하게 고칠 필요가 없었다
- **왜 색상을 스스로 정하지 않고 스킬 검색 결과를 거쳤나** — `.claude/rules/coding.md`상 큰 디자인 판단은 근거 없이 임의로 정하지 않는다는 원칙에 따라, 검색 데이터를 참고 자료로 삼아 결정했다
- **왜 로즈 팔레트를 다시 블루로 바꿨나** — 서비스명 "Polistagram"의 유래인 옛 Instagram 로고(파란 그라데이션 + 필기체)를 레퍼런스로 받아서, 브랜드 연상이 더 뚜렷한 블루 계열로 재조정했다. `match.html`도 같은 이유로 함께 맞췄다
- **왜 Streamlit을 도입하지 않았나** — 사용자가 프레임워크를 Streamlit으로 바꾸자고 제안했지만, `CLAUDE.md` 11절에 "빌드 도구 없는 단일 HTML/CSS/JS"로 이미 확정돼 있는 방침과 정면으로 충돌하는 스택 변경이었다. `.claude/rules/coding.md`상 기술 스택 변경은 임의로 결정하지 않는 항목이라, 먼저 사용자에게 확인했고 기존 방침을 유지하기로 했다 (실제 코드 변경 없음)

## 10. 배운 것

1. CSS 프레임워크(Pico.css)가 변수 기반으로 설계돼 있으면, 커스텀 CSS를 거의 안 써도 테마 전체를 바꿀 수 있다.
2. 다국어(한글) 서비스에서는 폰트 페어링을 고를 때 "그 폰트가 실제로 이 언어 글자를 지원하는가"부터 확인해야 한다.
3. `max-height` + `transition`만으로도 JS 애니메이션 라이브러리 없이 "접기/펼치기" UX를 만들 수 있다.
4. 여러 화면(`index.html`, `match.html`)이 색상 값을 각자 하드코딩하고 있으면, 팔레트를 바꿀 때 한쪽만 고치고 다른 쪽을 놓치기 쉽다. 화면이 더 늘어나면 색상 값을 한 군데(CSS 변수 등)로 모으는 것도 고려할 만하다.

## 11. 현재 한계

| 한계 | 내용 |
|---|---|
| 생년월일 미래 날짜 검증 없음 | `<input type="date">`가 형식과 자동 넘김은 기본 제공하지만, 미래 날짜 선택은 막지 않음 (확인만 하고 보류) |
| 카드뉴스 디자인 미착수 | 이번 재디자인은 프로필 입력 폼과 `match.html` 색상 통일까지만 다룸, 정책 카드 자체의 시각 디자인은 아직 안 만듦 |
| 색상 값이 파일마다 하드코딩됨 | `index.html`은 Pico CSS 변수로 관리되지만 `match.html`은 색상 값을 각 규칙에 직접 적어둬서, 팔레트를 또 바꾸면 두 파일을 각각 손봐야 함 |
